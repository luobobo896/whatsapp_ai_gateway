## 分项明细

### T1 用户登录
- 平台 `/api/auth/login`：错误密码 401 `AUTH_INVALID`（中文文案，bcrypt 校验 ~2.3s）；正确登录 204 + HttpOnly cookie；`/api/auth/me` 返回 CSRF 与自动选择的租户；登出后 me→401。
- `/api/ios-agent/v1/gateway/register`：201 返回 `{token(64hex), tenantId}`，明文仅一次；同名再注册轮换凭证（同 gateway id，旧 token 立即失效→重拨 4001）。
- WSS 鉴权：无效 token 先升级后 4001 `gateway token invalid`（客户端能拿到关闭码而非 HTTP 错误）；hello 名与凭证名不一致→4004（防窜名，服务端留有 `hello name mismatch` 告警）。
- 真实 App（浏览器实测）：登录框输入账号→平台校验→自动签发→凭证落盘→RestartCloud 热重连→顶栏显示「测试租客 / 平台管理员 · 连接于 …」、pill 绿色「已连接平台」；服务端确认 hansons-MacBook-Pro 于 19:21:00 轮换新凭证并在线。
- 限流：登录失败计数按 IP+邮箱双主题（5 次/5 分钟锁 15 分钟），本次未触发（仅 1 次错误尝试）。

### T2 登出
- 平台登出：session 删除，me 401。
- 网关 Web 登出（POST /api/logout）：仅撤销本地 web 会话（登录框回归）；**云通道设计上保持**——登出后服务端 last_seen 持续刷新（19:22:20），UI 显示「云通道 在线」。
- 强制登出等价路径（吊销）：管理端 revoke→在线连接 ~2s 内 4005 `gateway credential revoked`；后续重拨 4001 拒绝。轮换（重新登录）即恢复。

### T3 指令下发
- `POST /api/ios-devices/:id/broadcast`：网关在线→`pushed:true`+running，dispatch 与 REST 201 同秒到达网关；模拟执行回传 item:result×3 + task:summary→平台任务 done 3/3；DB 明细 sent_at/状态与 REST 完全一致。
- 输入校验：非大陆手机号 422 `INVALID_FIELDS` 并指明规则（仅支持 11 位 1 开头或 86/+86 前缀）。
- `easytier:config` 下发：`pushed:true`，网关收到完整配置（租户托管密钥、自动分配虚 IP 10.168.1.99）。

### T4 重新下发（断线补推）
- 网关离线创建任务：`pushed:false`、状态 pending。
- 重连（hello+device_list 后）：~50ms 内收到 task:dispatch 补推→执行→done 2/2。
- 部分完成场景（1/3 已 sent，running）：重连后整任务重推，网关重报全部 3 条，服务端对已终态条目去重，最终 done 3/3——**at-least-once + 幂等闭环成立**。

### T5 停止与启动
- 在线取消：REST 200 与网关收到 task:cancel 间隔 ~5ms；网关对未执行条目回传 cancelled；DB=1 sent+3 cancelled，任务 cancelled，三层一致。
- 离线取消：DB 直接终态；重连后**不**补推已取消任务（无幽灵下发）。
- easytier（真实 App REST）：stop→进程清零/running:false；start→新 pid、mesh 重入网（2 peers）；restart→全程 11s、新 pid、2 peers；`sudo -n` 免密无弹窗。
- WDA 设备 activate/stop：本机当前 0 台 USB iPhone，**未实机验证**（仅单元测试覆盖停止/激活路径），列入缺口。

### T6 断线重连与稳定性
| 场景 | 结果 |
|---|---|
| SIGKILL 异常断开（无关闭帧） | 服务端同秒检测（19:13:55 杀=19:13:55 offline），设备标 offline |
| 心跳超时 | 无心跳连接 46.8s 被 4005 `gateway heartbeat timeout` 踢线（设计 40s+10s reaper 扫描，实测在窗口内） |
| 单会话约束 | 同名新连接拨号→旧连接立即 4002 `replaced by new gateway connection` |
| 重复上报幂等 | 已终态 item 连报 3 次→DB 计数/sent_at 不变 |
| 瞬时网络抖动 | 19:06 出现 2 次 WSS 拨号 EOF＋1 次首页超时（跨境链路），随后 8/8 拨号成功；真实网关退避重连可覆盖（见 T7 实证） |

### T7 重启
- 平台服务重启（systemctl restart whatsapp-ai）：存续连接以 EOF 断开（无关闭帧，与 README 描述一致）；**真实网关 28s 内自动重连**（19:17:26 重启→19:17:54 last_seen 刷新），无需人工干预。
- 网关进程重启（kill 内部 gateway 进程）：旧进程 ~8s 优雅退出→守护进程拉起新进程→14s 内 Web 恢复 200→云通道自动重连（19:24:28）→easytier Recover 自愈（新 pid、2 peers）。

- 网关仓库：`go test -race -count=1 ./internal/gateway ./internal/wda` → ok（含重连相关 executor/webauth/离线收口等 16 个测试文件）。
- 平台仓库：`internal/handler`（含 gateway_ws/auth/mobile 等）＋ `internal/connector` → ok。

## 发现的问题

### F-1（中）心跳超时与凭证吊销共用关闭码 4005，客户端误分类
- 位置：服务端 `internal/handler/gateway_ws.go` reaper（KickGatewayByName 4005）；客户端 `internal/gateway/cloud.go:123,131` 仅按关闭码分类。
- 影响：心跳超时（NAT 黑洞、休眠恢复、单向丢包）时凭证仍有效，但客户端走「凭证吊销」分支——60s 慢退避＋UI 红点提示「平台已吊销该网关凭证…请重新签发」，误导用户重登且拖慢自愈。
- 建议：服务端为心跳超时启用独立关闭码（如 4006），或客户端解析 close reason 区分两种 4005。

### F-2（低）未登录时状态 pill 文案误导
- Web 未登录时 `/api/cloud`、`/api/easytier/status` 403，pill 显示「云状态读取失败」、组网「未启用」（实际 easytier 在跑）。建议区分未登录与真实故障。

### F-3（低）HK 链路偶发抖动
- 测试窗口内 2 次拨号 EOF＋1 次首页超时，均可自愈；跨境 DNS/链路因素。商用建议生产域名就近接入＋拨号失败率监控。

### F-4（低，待复核）自动化环境下按钮点击被拦截
- 内嵌浏览器中 Playwright 可点性点击「登录/登出」超时，DOM 节点点击正常；疑为环境遮罩问题，建议手动浏览器复核一次。

## 缺口与后续建议
1. WDA 设备级启停（activate/stop/watchdog 自愈）需在带 USB iPhone 的网关机上回归一遍。
2. 真实 WhatsApp 发送长稳（≥72h）与失败重试/熔断（连续失败 5 次熔断、设备不可达收口）实测。
3. 修复 F-1 后补一轮心跳超时场景的客户端行为验证。
4. 多网关并发（≥10 实例）压测与监控告警接入（连接数、拨号失败率、任务积压）。

## 商业可用性评估
- **功能完整性**：登录/凭证生命周期/下发/重推/取消/启停/重启自愈全链路可用，与设计文档（三端串联 v6）一致。
- **稳定性**：异常断开、心跳超时、单会话冲突、平台重启、进程被杀五类故障全部自愈；实测恢复时间：平台重启 28s、进程重启 14s、easytier 重启 11s、补推 <1s、cancel 送达 5ms。
- **数据一致性**：at-least-once 上报 + 服务端幂等去重成立；任务/明细在 REST、WSS、DB 三层一致。
- **结论**：**达到小规模商用试运行（pilot）标准**。规模商用前置条件：修复 F-1、补齐 WDA 实机与 72h 长稳回归、接入监控告警；F-2/F-3/F-4 为体验优化项。
