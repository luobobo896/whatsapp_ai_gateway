# 三端联调记录：连接稳定性 + 发送精准度优化（2026-08-15）

三端：云平台（hk.hsddns.com，WSS + EasyTier 中继）↔ 本地网关（Mac mini，本项目）↔ iPhone 真机（WDA）。

## 一、问题与根因（按证据）

### 连接不稳定

| # | 根因 | 证据 | 修复 |
|---|------|------|------|
| 1 | EasyTier 中继只配 UDP peer，网络路径丢 UDP | `/tmp/easytier-gateway.log` 2 小时内 2350 次 `connect timeout`、0 次成功；同主机 TCP 11010 探测通 | `writeTOML` 生成 udp+tcp 双 `[[peer]]`，easytier 自动选可用通道 |
| 2 | WDA 数据通道只有手机 Wi-Fi 一条路，USB 仅用于发现/激活 | 手机 Wi-Fi 全断（ping 100% 丢包、ARP incomplete）时 USB 仍在线、WDA 进程仍活 → 假在线；15:18 起本地两台设备任务全部失败 | 新增 iproxy USB 隧道（`usbmux.go`），看门狗/执行器/管理页全部隧道优先 |
| 3 | 多设备同轮激活共用同一个临时 xctestrun，UDID 注入互相覆盖 | `wda-59524996.log` 内打出 `WDA_DEVICE_UDID=4886...`（另一台的 UDID） | 临时文件按 UDID 隔离（`wdamanager.go`） |
| 4 | WDA 启动失败（签名/信任）后看门狗每 30s 重拉 xcodebuild，重试风暴 | `4886579a` 反复 `exit status 65`，日志为 `invalid code signature ... not been explicitly trusted` | 启动 2 分钟内退出 → 5 分钟冷却并给出明确错误；管理页手动「激活」可清除冷却 |
| 5 | WDA /session 瞬时 500 一次即判失联、整任务中止 | 历史明细 5 条 `Server error '500 ' for url .../session`，对应任务 `device_unreachable` | 执行器对可达性类错误原地重试一次（打开会话幂等，无重复发送风险） |

### 发送不精准

| # | 风险 | 修复（`internal/wda/whatsapp.go`） |
|---|------|------|
| 1 | 深链 HTTP 成功 ≠ 会话打开：老 iOS 不跳转/号码无效只弹窗时，可能停留在上一条明细的会话，把消息发给**错误的收件人** | 深链后必须等到输入框出现且（标题含号码时）与目标一致才继续，否则走聊天列表/搜索兜底（`chatOpenedFor`） |
| 2 | 点发送后不校验，点击未生效也上报 sent | `confirmSent`：轮询输入框文本已清空（5s）；仍残留原文报 `send unconfirmed` 错误 |
| 3 | iOS<16.4 未知号码搜索兜底等待不足（iPhone 7 / iOS 15 结果出得慢） | 搜索后 4s + 2s 两次窗口找联系人 cell |

另：明细缺手机号已由既有逻辑拒绝（今日 8 例，属平台侧数据问题，需在平台端校验）。

## 二、验证结果

- `go build` / `go vet` / `go test -count=1 ./...` 全绿；新增 `usbmux_test.go`、`whatsapp_send_test.go`（发送确认、深链校验、瞬时错误分类）、`executor_offline_test.go`（离线剔除、坐标解析）。测试曾抓到 Go 超时错误文本实际为 `context deadline exceeded`，已补进重试判定。
- EasyTier：peer `hk-controller` 经 **tcp** p2p 连接（丢包 0%），mesh 恢复。
- USB 隧道：`usb tunnel up` ×2；手机 Wi-Fi 全断情况下 iPhone 7 Plus 经 `127.0.0.1:<port>` `/status` 200、`devices.json` `ok=true`、`CreateSession`（WhatsApp 冷启动 15.3s）+ 删除会话成功——与执行器同一调用路径。
- 崩溃冷却：`4886579a` 签名问题不再重试风暴，日志明确提示需人工信任开发者证书。
- 云通道：重启后 WSS 秒连，`device_list` 上报 iPhone 7 Plus online。

## 二·补（第二轮：任务下发行为）

- **离线设备任务剔除**：`processTask` 开始时先做 4s 快速探活（USB 隧道优先、Wi-Fi 兜底），
  不可达则全部可发明细立即标 `failed`（错误文案「设备离线（WDA 不可达），任务被网关拒绝，
  请转派在线设备后重试」）并上行 `task:summary`（`device_unreachable`），平台可马上转派；
  不再逐条空耗 40s 超时。缺手机号明细属数据校验，仍在剔除前按「缺少手机号」收口
  （全空号任务汇总为 `completed`，与既有语义一致）。
- **LLM 视觉兜底扩展到输入框**：配置了 `llm`（或平台下发 `model:config`）时，
  消息输入框选择器找不到也会走「截图 → 视觉模型定位坐标 → 点击 → 重试选择器」；
  未配置则与原来完全一致（纯选择器）。发送键兜底保持不变。

## 二·补二（第三轮：数据准确与状态稳定）

- **字段无缺失**：`itemRecord` 增加 `serial`/`device_name` 落盘；断线补报（`ResendPersisted`）
  原样携带，老记录缺字段时按 udid 从 devices.json 兜底补全后上行。
- **明细分组按设备**：`/api/items` 分组键为设备（udid），组头展示序列号+名称；
  设备已从配置移除时用明细记录落盘的序列号兜底，分组标识不缺字段。
- **在线状态不抖动**：① 任务执行中（busy）跳过健康检查覆盖，保留上一轮健康状态；
  ② 任务收尾按真实探活上报（online/offline），不再无条件报 online；
  ③ WDA 激活后 90 秒宽限期（`wdaStartGrace` 首次接线）：进程已拉起但监听/隧道
  未就绪时仍报 online，消除「激活成功→短暂离线→又在线」抖动。
- **停一台只停一台**：隧道拆除防抖——ioreg 偶发空结果时整轮跳过对账（不误拆全部隧道）；
  单台设备连续 2 轮确认从 USB 列表消失才拆其 iproxy，其余设备不受影响。
- **自动重连矩阵**：云 WSS 指数退避重连；EasyTier 双协议 peer 自愈；iproxy 隧道每轮
  看护对账自动补起；WDA 看护重激活（签名类故障限速 5 分钟一次，防重试风暴）。

## 四、生产级严格验证（第四轮）

### 加固项（本轮代码变更）
- **easytier 崩溃自愈**：`Supervise()` 看护拉回（意图标记：主动停止绝不自动重启；
  2 分钟限速防崩溃风暴；`startMu` 串行化手动/自愈并发启动）。
- **循环 panic 防护**：看护每轮与云会话均带 recover，单轮异常不拖死自愈体系。
- **任务队列防阻塞**：队列 16→256，超限 3 秒有界背压后丢弃告警（保护云读循环）。
- **计数单点收敛**：发送计数移入 `finishItem`（落盘=统计永远一致）；修复离线剔除/
  无 IP 路径不计数、空 udid 污染 metrics 桶两个不一致源（后者由 8 连跑 race 测试抓出）。
- **pprof 观测端点**：`/debug/pprof/*` 仅本机回环可访问（非本机 404），生产泄漏排查用。

### 生产运行口径
- 自愈矩阵：云 WSS（指数退避）/ EasyTier（双协议 peer + 进程看护拉回）/ iproxy 隧道
  （每轮对账重建）/ WDA（看护重激活，签名类故障 5 分钟限速）。
- 单点故障隔离：隧道、WDA、激活、统计均按 UDID 隔离，任一设备故障不影响其余设备
  （注入 1/2 实测验证）。
- 已知运维项：iPhone Plus-2 证书信任已恢复（22:41 起 ok=true）；远程 iPhone 待对端
  easytier 节点上线；results 目录无自动清理（按当前量约 20MB/天，建议后续加保留策略）。
