## 〇.5 云通道设置功能（2026-08-17 补丁，用户报告 bug：无登录登出、ws_url 无处填写）

**根因**：main-test 页面本无 cloud 配置入口（源码形态靠手改 devices.json）；全新安装 enabled=false → `PasswordRequired=false` → 登录遮罩不出现、无登录登出。

**修复三件套**（均实测通过）：
1. **全新安装预填默认**：库内无任何 cloud 配置时预填 `DefaultCloudWSURL` + enabled=true → 开箱即出现登录遮罩（`passwordRequired:true` 实测）；已有配置（含迁移）不覆盖（单测覆盖）。
2. **页面「云通道设置」面板**（设备总览顶部）：ws_url / 网关名 / 启用开关 / token（可选，留空保持）+ 保存；`GET/PUT /api/cloud/config`（GET 脱敏；PUT 更新落库并 `EnsureCloudLoop()` 热拉起/触发重连——CloudLoop 由 `cloudLoopRun` 原子位管理，冷启动未启用后首次配置可再拉起，`main.go` 改用 `SetAppContext+EnsureCloudLoop`）。
3. **鉴权白名单 + 防死锁**：`/api/cloud/config` 公开（配置平台地址是登录的前置条件，填错 ws_url 时若要求登录会死锁）；写操作 CSRF 带「同源 Origin / 无会话无 Origin（curl 调试）」放行规则，跨站 Origin 实测拒绝（`{"error":"invalid csrf token"}`）。

**端到端实测**（全新 state 启动）：登录遮罩出现 ✓；未登录 GET/PUT 设置成功且热更新（日志 `cloud config updated`）✓；云通道以默认 ws_url 连平台、无凭证被 4001 拒绝并退避重试（登录后自动签发即恢复）✓。

另：排查发现之前一次安装到旧版二进制的根因是 hdiutil 重复挂载产生多个同名编号卷（"WDA Farm Gateway 2/3/4"），`cp` 命中旧卷——打包脚本无此问题，重装时需先卸载全部同名卷并校验二进制特征。

## 〇、单包自包含验证（2026-08-17 补充，用户要求：一个安装包解决所有问题、不依赖开发环境）

### 0.1 功能全集枚举（以 main-test 源码为准）

- **全部 16 条路由**：`/`、`/api/login|logout|session|cloud|devices|devices/|items|llm|metrics|tasks|tasks/`、`/api/easytier/status|config|action`、`/debug/pprof/`——逐条新旧并行对比，**状态码与响应结构 18/18 一致**（pprof 首页数字归一后逐字一致，差异仅为动态计数器）。
- **外部命令全集**（`exec.Command` 扫描）：xcodebuild/xcrun（Xcode）、security/PlistBuddy/ioreg/sudo/osascript（系统自带）、iproxy/ideviceinfo（**随包**）、easytier（**随包**）。
- **前端零外链**：index.html 无任何 CDN/外链资源，离线可用。

### 0.2 发现并修复的两个遗漏

1. **ideviceinfo（序列号查询）未随包**：补进 `Resources/bin/`（`discover.go` 定位链增加 bundle 路径）。
2. **ideviceinfo 依赖闭包缺失**：其闭包含 libimobiledevice-1.0.6/libssl.3/libcrypto.3（iproxy 闭包没有）——打包脚本收集起点扩为 iproxy+ideviceinfo 双起点。

### 0.3 dyld 挂死问题与最终打包方案（本轮最大坑）

- **现象**：`install_name_tool` 修改过的 iproxy/ideviceinfo 在 macOS 15 dyld4 下启动死循环（sample 栈：`createMinimalInfo→isMachO`），无论 ad-hoc 重签、remove-signature+重签、lipo thin 均无法挽救；挂死进程进入 **UNE 不可中断睡眠，kill -9 无效**（本期实验机上残留 7 个，重启自清）。
- **对照实验**：Homebrew 原版二进制始终正常 → 问题确凿为 Mach-O 修改本身。
- **最终方案**：**二进制原样拷贝、零修改**；壳与 gateway 给子进程注入 `DYLD_LIBRARY_PATH=<bundle>/Resources/lib`（dyld 按 leaf name 优先命中包内 dylib，`DYLD_PRINT_LIBRARIES` 实证加载路径为包内），客户机有无 Homebrew 均确定性走包内依赖。`usbmux.go`/`discover.go` 的 exec 显式注入，不依赖壳。

### 0.4 纯净客户机模拟（端到端实测）

模拟条件：DMG→本地安装、`PATH=/usr/bin:/bin:/usr/sbin:/sbin`（无 Homebrew）、干净 state、全部资源指向包内（`-project/-static/WDA_GATEWAY_RESOURCES`）。

## 四、已知边界与遗留

1. **ad-hoc 签名**：本机无 Developer ID Application 证书。客户首次打开需右键→打开（安装说明已写）。升级路径：`xcrun notarytool store-credentials …` 后 `NOTARY_PROFILE=… sh scripts/build-dmg.sh` 自动签名+公证。
2. **iPhone 17（新式 CoreDevice UUID）不在设备列表**：`discover.go` 的 UDID 正则仅匹配 40 位十六进制（老式 UDID），main-test 基线同样如此——**现状限制非本次回归**；如需支持新设备需扩展发现层（二期）。
3. **WKWebView 复制粘贴**：已通过标准 Edit 菜单修复，需用户在真机 GUI 上最终确认 Cmd+C/V 手感。
4. easytier root 实例强杀依赖 sudoers 免密规则（`setup-easytier-sudo.sh` 一次性授权）；未授权机器上仅能杀普通实例，root 残留会记日志。
5. WDA 激活链路未做真机实测（现网设备 auto_reactivate 关闭防抢占；`wdamanager.go` 仅新增可选 team 透传，默认路径与基线同源）。客户环境首次激活会触发 xcodebuild build-for-testing（数分钟）。
