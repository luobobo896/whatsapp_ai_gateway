# macOS 桌面客户端（DMG）打包交付方案

> 目标：把 WDA Farm Gateway 打包成 DMG 安装包，客户安装成桌面应用程序做验证测试。
> 要求：桌面端业务逻辑与现有 Web 页面完全一致、功能不减；同时保留 HTTP 端口（8300）可直接访问。
> 关联：`/Users/hanson/work/个人文档/whatsapp_ai_ios/WhatsAppDeviceAgent`（WDA 工程）的打包策略。

---

## 1. 结论（TL;DR）

- **形态**：原生 macOS App（Swift 菜单栏壳 + WKWebView 窗口），内嵌现有 Go `gateway` 二进制作为子进程，监听 `0.0.0.0:8300` 不变。窗口内加载 `http://127.0.0.1:8300/`，**与网页版同一份代码、同一套 API、同一套登录鉴权**，功能天然 100% 一致；局域网其他设备仍可用 `http://<Mac-IP>:8300` 访问。
- **配置存储 SQLite 化**：`devices.json` 迁入 `data/gateway.db`（见 §8.1），打包模板逻辑消失，客户侧不可手改坏配置。
- **架构决策已定**：仅出 **arm64** 包（Apple Silicon Mac），不做 Intel。
- **签名决策已定**：验证阶段用**个人付费开发者账号**——壳 App 用其 Developer ID 证书签名 + notarytool 公证（客户双击即装），WDA 用其开发证书预签（客户手机 UDID 注册进个人账号）；后续迁移公司账号的步骤见 §5.3。
- 为保证「打包后所有功能保持可用」，逐功能核对见 **§11 功能完整性核对矩阵**；两个必须适配的点：**iproxy（USB 隧道必需）随包分发**、**easytier 固定路径安装**（sudoers 路径假设）。
- **WhatsAppDeviceAgent（WDA）**：**源码工程随 DMG 一起打包**（约 24MB，剔除 .git 后），因为网关激活 WDA 需要 `xcodebuild` 现场编译安装到 iPhone。客户 Mac **必须装 Xcode**（当前架构硬依赖，见 §5）。
- **最大门槛不在打包，在客户 Mac 环境**：Xcode（约 12GB）+ Apple 签名证书策略 + macOS 权限弹窗（本地网络/传入连接）+ 手机侧信任开发者证书。
- **必须清理敏感数据**：当前 `devices.json` 含云平台 token、**阿里云 LLM 付费 api_key**、我们自己的手机 UDID/IP，绝不能随包带出。

## 2. 现状盘点（决定打包方式的事实）

### 2.1 gateway（Go，纯静态，适合打包）

| 事实 | 来源 | 对打包的影响 |
|---|---|---|
| 纯 Go、无 CGO（`modernc.org/sqlite`） | `go.mod` | 可直接 `go build` 出单文件 arm64 二进制，无运行时依赖 |
| 监听 `0.0.0.0:8300`（`-listen` 可改） | `cmd/gateway/main.go:22` | "开放端口可访问"需求已满足，壳无需改动 |
| 所有资源路径相对 config 目录，且均有 flag 可覆盖（`-config/-project/-static/-derived`） | `cmd/gateway/main.go:19-24` | 壳用参数把路径指到 app bundle 内资源 + 用户可写数据目录，**Go 侧几乎零改动** |
| WDA 工程默认 `config目录/../whatsapp_ai_ios/WhatsAppDeviceAgent` | `cmd/gateway/main.go:39-41` | 打包后用 `-project` 显式指定，摆脱目录结构假设 |
| 数据落盘：`data/sessions.db`（SQLite）、`data/results/`、`data/easytier.*` | `main.go:56`、`easytier.go` | app bundle 内只读，数据必须放 `~/Library/Application Support/` |
| Web 登录：邮箱/密码转发云平台 `/api/auth/login`（由 `ws_url` 推导） | `webauth.go:155` | 客户需能访问 `wss://hk.hsddns.com`，且在平台有账号 |
| 优雅停机：SIGTERM → 关 WSS 会话 → 15s 退出 | `main.go:64-93` | 壳退出时发 SIGTERM 即可，已就绪 |

### 2.2 gateway 调用的外部命令（客户 Mac 依赖来源）

| 命令 | 来源 | 必需性 |
|---|---|---|
| `xcodebuild`（build-for-testing / test-without-building） | **Xcode** | 必需（激活 WDA 的核心路径） |
| `xcrun devicectl list devices` | **Xcode** | 必需（USB 设备发现） |
| `security find-identity` | macOS 自带 | 必需（取签名身份） |
| `/usr/libexec/PlistBuddy` | macOS 自带 | 必需（注入 xctestrun 环境变量） |
| `ioreg` | macOS 自带 | 必需（USB UDID 发现） |
| `iproxy` | **Homebrew libimobiledevice** | **必需（USB 隧道）**：`usbmux.go` 的 USB 直连 WDA 流量全部经 iproxy 转发，缺失则 USB 隧道功能不可用（设备退回 Wi-Fi 直连） |
| `ideviceinfo` | Homebrew libimobiledevice | 可选（仅取硬件序列号，缺失只影响显示；与 iproxy 同包安装） |
| `tools/easytier/easytier-core\|cli`（29MB，随包） | 项目自带 | 可选（后备组网通道，默认关闭） |

### 2.3 WhatsAppDeviceAgent（WDA）

- 是跑在 **iPhone 上**的 WebDriver/XCTest runner，不是 Mac 程序，**不能也不需要"编译进"桌面 App**；它的消费方式是被 `xcodebuild` 编译安装到手机。
- 网关激活链路：`xcodebuild build-for-testing`（首次，数分钟）→ 每台手机 `test-without-building` 常驻。
- 工程里写死 `DEVELOPMENT_TEAM = A3JP3VUZ78`、`CODE_SIGN_STYLE = Automatic`（`project.pbxproj`）→ **客户手机上装 WDA 必须过签名这一关**，见 §5.3。
- 体量：源码约 24MB（剔除 `.git` 66MB 后），随包无压力。

## 3. 客户端形态选型

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. WebView 壳（推荐）** | Swift/AppKit 菜单栏 App，主窗口 WKWebView 加载 `http://127.0.0.1:8300/`，子进程拉起 `gateway` | 真正"桌面应用"观感；UI 100% 复用现有页面；零 Node/Rust 运行时；端口照常开放 | 需注意 WKWebView cookie/持久化（用 `WKWebsiteDataStore.default()` 即可） |
| B. 菜单栏 + 系统浏览器 | 壳只拉起 gateway 后 `open http://localhost:8300` | 实现最简（1 天） | 不像"客户端"，客户感知是网页快捷方式 |
| C. Electron/Tauri 重写壳 | Node/Rust 生态 | 生态丰富 | 引入大运行时/新工具链，违背"功能不少、改动最小" |

**选 A**。两种形态都满足"端口可访问"：gateway 照旧监听 `0.0.0.0:8300`，局域网任意设备可开管理页。

## 4. App Bundle 结构与数据目录

### 4.1 Bundle 布局（只读资源）

```
WDAFarmGateway.app/Contents/
├── Info.plist                  # LSUIElement=false；网络/USB 用途说明（NSSystemAdministrationUsageLabel 等）
├── MacOS/
│   ├── WDAFarmGateway          # Swift 启动壳（菜单栏 + WKWebView 窗口 + 子进程管理）
│   └── gateway                 # 现有 Go 二进制（go build 产物，arm64）
└── Resources/
    ├── static/index.html       # 现有管理页（或改为 go:embed，见 §8）
    ├── WhatsAppDeviceAgent/     # WDA 源码工程（rsync 剔除 .git）
    ├── tools/easytier/         # easytier-core|cli（可选，默认关闭）
    ├── scripts/                # setup-easytier-sudo.sh 等
    └── AppIcon.icns
```

### 4.2 可写数据目录（与 bundle 分离，避免破坏签名）

```
~/Library/Application Support/WDAFarmGateway/
├── gateway.db                 # 配置+设备库（首次启动自动建库，内置默认值；见 §8.1）
├── data/                      # sessions.db / results/ / easytier.*（gateway -state 指向这里）
└── logs/gateway.log           # 壳把子进程 stdout/stderr 重定向到这里
```

### 4.3 启动壳职责（约 300~400 行 Swift）

1. 单实例保护（已运行则激活已有窗口）；端口被占时提示而非崩溃。
2. 首次启动初始化数据目录（建目录即可，库由 gateway 首次运行自建）。
3. 拉起子进程：
   `gateway -state <AppSupport> -project <Resources>/WhatsAppDeviceAgent -static <Resources>/static -listen 0.0.0.0:8300`
4. 轮询 `/` 就绪 → 打开 WKWebView 窗口；子进程意外退出 → 菜单栏提示 + 一键重启。
5. 退出菜单项 → 向 gateway 发 SIGTERM（优雅停机已实现）→ 等 15s → 强杀。
6. 「打开日志目录」「复制访问地址 http://<本机IP>:8300」等便利入口。

## 5. WhatsAppDeviceAgent 打包策略（用户重点问题）

### 5.1 能不能打包进去？

**能，且建议打包源码工程**（剔除 `.git`，约 24MB）。理由：`ensureBuilt()` 首次激活就要对 WDA 工程跑 `xcodebuild build-for-testing`，客户机器上没有这套源码就完全无法激活设备。DMG 内放 `Resources/WhatsAppDeviceAgent/`，启动壳用 `-project` 指过去即可。

同时可选：把我们预编译好的 `WebDriverAgentRunner_iphoneos*.xctestrun` + Products 目录一并放入（`-derived` 指向），客户首次激活省 3~10 分钟构建时间。**注意预编译产物绑定我们的签名证书**，是否随包取决于 §5.3 的证书决策。

### 5.2 绕不开的客户侧依赖：Xcode

`xcodebuild`（编译/启动 WDA）和 `xcrun devicectl`（USB 发现）都来自 Xcode，**当前架构下客户 Mac 必须安装 Xcode（~12GB）并 `xcode-select` 指向它**。彻底去 Xcode 化（改用 go-ios/tidevice 的 XCUITest 私有协议直接启动 WDA）是较大的改造，不建议本期做，可作为二期目标。

### 5.3 签名与证书（已决策：暂用个人付费开发者账号）

**决策**：验证阶段全部使用个人 Apple Developer 付费账号（当前工程写死的 `DEVELOPMENT_TEAM = A3JP3VUZ78` 即个人 Team），后续迁移公司账号。

| 对象 | 证书类型 | 说明 |
|---|---|---|
| 壳 App（DMG 内 WDAFarmGateway.app） | **Developer ID Application**（个人账号下创建） | `codesign --deep --options runtime --timestamp` + `notarytool` 公证 + `stapler` → 客户双击即装，无 Gatekeeper 拦截；公证用 App 专用密码 |
| 内嵌二进制（gateway / easytier-core / iproxy） | 随 `--deep` 一并签名 | 不签会被 Gatekeeper 拦子进程 |
| WDA（装到 iPhone） | 个人 Team 的 Apple Development 证书预签 | 构建机 Xcode 登录个人 Apple ID；客户提供手机 UDID → 构建时 `-destination id=<UDID> -allowProvisioningUpdates` 自动注册设备并生成 profile（付费账号 100 台/年额度，足够验证期）→ 客户手机「设置→通用→VPN与设备管理」信任个人开发者证书 |

**后续迁移公司账号的动作清单**（记录备查）：WDA 的 `DEVELOPMENT_TEAM` 换新 Team ID（参数化后改配置即可）；壳 App 换公司 Developer ID 证书重签重公证；已在客户手机上的 WDA 需重装并重新信任新证书；easytier/iproxy 不受影响。

### 5.4 iPhone 侧要求（写给客户的安装说明）

- iOS 16+ 需开「开发者模式」（设置→隐私与安全性）。
- 首次 USB 连接在手机上点「信任此电脑」完成配对。
- 安装 WDA 后在「设置→通用→VPN与设备管理」信任对应开发者证书。
- 手机与 Mac 同一局域网（Wi-Fi IP 自动发现依赖网关局域网扫描）+ WhatsApp 已登录。

## 8. 需要的代码改造点（都很小）

### 8.1 devices.json → SQLite（配置存储迁移，已决策）

**可行性依据（已核实源码）**：所有持久化入口收敛在 `internal/gateway/config.go` 一个文件——`LoadConfig`（唯一读入口）、`Save`/`SetCloudToken`/`SetLLM`/`RemoveDevice`（全部写入口，调用方在 watchdog/web/gateway/cloud 共 9 处）；没有任何模块绕过 `Config` 直接读写 devices.json。`Config` 结构体与方法签名保持不变 → **只换持久化层，调用方零改动**。

- 库文件：`<state>/gateway.db`，与 sessions.db 同机制（`modernc.org/sqlite`，纯 Go 无 CGO，交叉/打包不受影响）。sessions.db 保持独立不动。
- Schema v1：
  ```sql
  CREATE TABLE IF NOT EXISTS meta   (key TEXT PRIMARY KEY, value TEXT NOT NULL);  -- schema_version
  CREATE TABLE IF NOT EXISTS config (key TEXT PRIMARY KEY, value TEXT NOT NULL);  -- cloud/llm/web/health_interval，value=JSON
  CREATE TABLE IF NOT EXISTS devices(udid TEXT PRIMARY KEY, data TEXT NOT NULL);  -- 每台一行 JSON（含 last_health 等缓存状态）
  ```
- `config.go` 改动：
  - `LoadConfig(path)` → `OpenConfig(stateDir)`：建库建表；**兼容迁移**——检测到旧 `devices.json` 且库为空时一次性导入，旧文件改名 `devices.json.bak`（老部署凭证不丢）；
  - `Save()` → devices 全量 upsert；`SetCloudToken()`/`SetLLM()` → 只写各自 config key（不再整文件重写）；`RemoveDevice()` → delete 行。
- `cmd/gateway/main.go`：`-config` 退役，新增 `-state <dir>`（默认当前目录，`GATEWAY_STATE_DIR` 同义环境变量）；`data/`、easytier、static、WDA 工程的路径锚点统一挂到 state 目录。
- 收益：watchdog 每 30s 持久化 `last_health` 从「整文件重写 JSON」变为行级更新；token/llm 热更新原子性更强；**打包侧不再需要模板 devices.json**（首次建库用代码内置默认值，敏感字段天然为空）。
- 损失（可接受）：失去手工编辑 JSON 的能力——排障改用 Web 页面/API，或 `sqlite3` CLI 直接查（macOS 自带）；README 快速开始章节需同步更新。

### 8.2 其余改造

1. **壳工程**：新建 `desktop/` Swift 工程（启动壳），此为新增主体工作量。
2. **iproxy 随包适配（功能完整性关键项）**：`usbmux.go` 的 `iproxyBin()` 查找链增加「bundle 内 `Resources/bin/iproxy`」；打包脚本从 Homebrew 拷贝 iproxy 及其依赖的 dylib 进 bundle，`install_name_tool` 改为 `@executable_path` 相对引用并随 `--deep` 签名。客户零 brew 依赖；退路是安装说明引导 `brew install libimobiledevice`。
3. **easytier 安装路径适配**：现 sudoers 放行 `$(pwd)/tools/easytier/easytier-core`（绝对路径），app 移动/更新即失效。改为安装到系统固定路径（`/usr/local/libexec/wda-gateway/easytier-core`，安装脚本从 bundle 拷贝），sudoers 放行固定路径；`easytier.go` 的 `binDir` 相应支持配置覆盖。
4. `wdamanager.go`：xcodebuild 透传 `DEVELOPMENT_TEAM`（配置增加 `signing.team`，空=工程默认 A3JP3VUZ78，为换公司账号预留）；`-derived` 默认值从 `/tmp` 改到 state 目录下。
5. （可选优化）`static/` 改 `go:embed`，index.html 进二进制，bundle 少一个目录且不怕客户误删。
6. 打包脚本 `scripts/build-dmg.sh`：go build → swift build → 组装 bundle（rsync WDA 源码剔 .git、拷 easytier/iproxy）→ codesign（个人 Developer ID）→ DMG → notarytool 公证 + stapler。

## 9. 敏感数据清理 checklist（打包脚本里强制执行）

- [ ] 仓库根的 `devices.json` **不入包**（SQLite 化后打包内容里本来就没有它）——当前文件含真实云 token、阿里云 LLM api_key（计费）、真实手机 UDID/IP，严禁带出；打包脚本用白名单组装而非整目录拷贝
- [ ] `data/` 整目录不带（sessions.db 会话、gateway.db 配置、历史发送结果含客户手机号）
- [ ] `data/easytier.json|toml` 不带（网络密钥）
- [ ] 两仓库 `.git/` 不带（含全部历史与凭证痕迹）
- [ ] `tools/easytier` 二进制可带（开源 BSD/Apache）
- [ ] WDA `PrivateHeaders/` 可带（WDA 项目自带）

## 10. 签名、公证与 DMG 制作

1. **壳 App 签名（已决策：个人账号 Developer ID）**：
   - 个人付费账号下创建 Developer ID Application 证书 → `codesign --deep --options runtime --timestamp --sign "Developer ID Application: <姓名> (<TeamID>)"`；
   - `notarytool submit --wait`（App 专用密码）+ `stapler staple`——客户双击 DMG 即用；
   - 内嵌的 `gateway`/`easytier-core`/`iproxy` 二进制随 `--deep` 一并签名，否则子进程被 Gatekeeper 拦。
2. **DMG**：`hdiutil create -format UDZO` 或 `create-dmg`（带 Applications 拖拽背景图）；卷内容 = `WDAFarmGateway.app` + `安装说明.txt` + `Applications` 符号链接。预计总体积 ~70MB（gateway 17MB + easytier 29MB + WDA 24MB）。
3. DMG 本身也走公证（`stapler staple *.dmg`）。

## 11. 功能完整性核对矩阵（打包后逐功能保持可用）

> 逐项核对源码得出的打包影响。前端已确认为纯 `fetch` 轮询（5s `refreshAll`）+ cookie 会话 + CSRF header，**无 WebSocket/SSE**，WKWebView 完全兼容。

| # | 功能 | 打包后可用性 | 前置/适配 | 验证方式 |
|---|---|---|---|---|
| 1 | Web 管理页（登录/设备管理/发送明细/组网区块） | ✅ 原样 | 同一 HTTP 服务，窗口与浏览器访问同一份页面 | 干净 Mac 登录后逐页面操作 |
| 2 | 局域网端口访问 `http://<IP>:8300` | ✅ 原样 | `-listen 0.0.0.0:8300` 不变；防火墙弹窗允许 | 他机浏览器访问并登录 |
| 3 | USB 设备发现 + 激活/看护 WDA | ✅ 原样 | 客户 Mac 装 Xcode；手机信任开发者证书 | 插 USB → 激活 → 心跳在线 |

| 6 | 云通道 WSS（设备上报/任务接收/断线自愈/凭证吊销踢出） | ✅ 原样 | 外网可达平台 | 平台下发任务 → 执行 → 结果回传 |
| 7 | WhatsApp 发送流程（深链/选择器/明细回传） | ✅ 原样 | 手机 WhatsApp 已登录 | 真机发送一条带明细的任务 |
| 8 | LLM 视觉兜底（截图定位发送键） | ✅ 原样 | 平台下发 model:config 或本地配置客户自己的 key | 构造选择器 miss 场景观察截图兜底 |
| 9 | easytier 后备组网通道（TUN） | ⚠️ 需适配 §8.2-3 | 固定路径安装 + sudoers 授权（一次性，默认关闭） | 平台下发 easytier:config → 启动 → peer 可见 |
| 10 | 会话持久化（SQLite，重启不丢登录态）+ 发送结果落盘 | ✅ 原样 | state 目录可写 | 重启 App 后会话/历史明细仍在 |

| 12 | 序列号显示（ideviceinfo） | ⚠️ 随包或 brew | 与 iproxy 同源（libimobiledevice） | 设备列表序列号列非空 |

**明确不迁移的**：Xcode 依赖（§5.2，客户 Mac 必装）；`cmd/wda-probe` 调试工具（内部用，不入包）。

## 12. 交付验证清单（发给客户前自测）

1. 干净 macOS 虚机/新用户：装 DMG → 启动 → 权限弹窗全部允许 → 管理页登录（平台账号）→ 设备列表出现。
2. USB 插 iPhone → 激活 WDA 成功 → 心跳在线 → 平台下发任务 → WhatsApp 发送成功 → 结果回传。
3. 局域网另一台设备访问 `http://<Mac-IP>:8300` 可登录操作（验证"端口开放"需求）。
4. 退出 App → gateway 进程无残留（`pgrep`）；重启 App 会话仍有效（sessions.db 落盘）。
5. 断网/平台重启场景：WSS 自动重连（已有指数退避）。
6. 反编译检查：包内 grep 不到任何真实 token/api_key/UDID。
